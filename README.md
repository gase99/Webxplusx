# A-Cut 2Dpro — جدول ورود اطلاعات قطعات

🌐 **نسخهٔ آنلاین:** https://gase99.github.io/Webxplusx/  
(با هر پوش روی شاخهٔ `main` مخزن `gase99/Webxplusx`، از طریق `.github/workflows/deploy.yml` به‌صورت خودکار روی GitHub Pages منتشر می‌شود.)

نرم‌افزار بهینه‌سازی برش دوبعدی ورق (در حال ساخت).
این بخش: **جدول ورود اطلاعات (Data Entry Table)** با React + TypeScript + Tailwind CSS، کاملاً راست‌چین و فارسی.

## اجرا

```bash
npm install
npm run dev      # اجرای محیط توسعه (Vite)
npm run build    # بررسی تایپ‌ها + بیلد نهایی
```

## تعاریف تخصصی

| اصطلاح | معادل | توضیح |
|---|---|---|
| **نوار** | Edge Banding | لبه‌چسب / نوار PVC روی لبهٔ قطعه |
| **فارسی** | Miter Cut (45°) | برش زاویهٔ ۴۵ درجه — روی نقشهٔ برش با علامت بصری مشخص می‌شود |
| **شیار** | Groove | شیار برای جاگذاری ورق ۳ میلی‌متری (پشت‌بند) |

## مدل دادهٔ هر ردیف — `src/types/part.ts`

```ts
interface CutPart {
  id: string;
  name: string;          // نام قطعه
  length: number;        // طول (mm)
  width: number;         // عرض (mm)
  qty: number;           // تعداد
  bandLength: 0 | 1 | 2; // تعداد لبه‌های نوار در طول
  bandWidth: 0 | 1 | 2;  // تعداد لبه‌های نوار در عرض
  farsiLength: 0 | 1 | 2; // تعداد لبه‌های فارسی در طول
  farsiWidth: 0 | 1 | 2;  // تعداد لبه‌های فارسی در عرض
  grooveLength: 0 | 1 | 2; // تعداد لبه‌های شیار در طول
  grooveWidth: 0 | 1 | 2;  // تعداد لبه‌های شیار در عرض
}
```

مقدار هر عملیات **۰ = بدون عملیات، ۱ = یک لبه، ۲ = هر دو لبهٔ مقابل** است.
`*Length` لبه‌های موازی با طول و `*Width` لبه‌های موازی با عرض قطعه را مشخص می‌کند.
متراژ نوار، فارسی و شیار با ضرب تعداد لبه در طول همان محور و تعداد قطعات محاسبه می‌شود.

## ساختار جدول — `src/components/DataEntryTable.tsx`

- هدر **دو سطحی**: سطح اول «نام قطعه | طول | عرض | تعداد | نوار | فارسی | شیار» و در سطح دوم،
  هر یک از ستون‌های نوار/فارسی/شیار به دو زیرستون «طول» و «عرض» تقسیم شده‌اند (`colSpan`)؛
  بقیهٔ ستون‌ها با `rowSpan={2}` ادغام شده‌اند.
- ستون **شمارهٔ ردیف** در ابتدا و ستون **عملیات** (تکثیر / حذف ردیف) در انتها.
- هر گروه رنگ متمایز دارد: نوار = سبزآبی (teal)، فارسی = قرمز/رز (rose)، شیار = کهربایی (amber).
- برای هر محور ورودی عددی **۰/۱/۲** وجود دارد؛ کلیدهای ↑/↓ مقدار را تغییر می‌دهند و
  کنار ستون **فارسی** آیکون مثلث/خط مورب + برچسب `۴۵°` دیده می‌شود.
- داده‌ها به‌صورت خودکار در `localStorage` مرورگر ذخیره می‌شوند.

## ناوبری با کیبورد (UX اصلی)

مدیریت فوکوس با `useRef` (نگاشت `rowId:field` → اینپوت) + `event.preventDefault()`:

| کلید Enter در… | رفتار |
|---|---|
| نام قطعه | فوکوس روی «طول» همان ردیف |
| طول | فوکوس روی «عرض» |
| عرض | فوکوس روی «تعداد» |
| تعداد | درج ردیف جدید بلافاصله بعد از ردیف جاری و فوکوس روی «نام قطعه» آن |

امکانات تکمیلی: جهت‌نمای ↑/↓ بین ردیف‌ها در همان ستون حرکت می‌کند، متن اینپوت هنگام فوکوس
انتخاب (Select) می‌شود تا بازنویسی سریع باشد، و ارقام فارسی/عربی (۰۱۲۳…) در ابعاد پذیرفته می‌شوند.

## فاز ۲ — موتور بهینه‌سازی برش (Guillotine) — `src/algorithm.ts`

منطق محاسباتی کاملاً مستقل از React است (فایل خالص TypeScript) تا در تست، سرور و
فاز ۳ قابل‌استفادهٔ مجدد باشد:

```ts
import { calculateLayout } from './algorithm';

const result = calculateLayout(parts, { length: 3660, width: 1830 }, { kerf: 4, allowRotation: true });
```

- **روش:** Guillotine Bin Packing — هر برش از یک لبه تا لبهٔ مقابل است، دقیقاً مثل
  ارهٔ پانل‌بُر کارگاه. فضای آزاد صفحه به‌صورت مستطیل‌هایی نگه داشته می‌شود که با
  هر جایگذاری با یک برش سرتاسری تقسیم می‌شوند (+ ادغام مستطیل‌های مجاور).
- **ترتیب چیدمان:** قطعات بزرگ اول — مرتب‌سازی نزولی بر اساس مساحت (تساوی: بزرگ‌ترین بُعد).
- **انتخاب جای قطعه:** Best Area Fit و در تساوی Best Short Side Fit، روی همهٔ
  صفحه‌های باز و در هر دو جهت (عادی و چرخش ۹۰ درجه). چرخش فعلاً یک گزینهٔ سراسری
  است؛ با آمدن «قفل گرین/رگهٔ چوب» به‌ازای هر قطعه جدا می‌شود.
- **مدل Kerf:** خوراک تیغه از سمت فضای باقی‌مانده گرفته می‌شود نه از خود قطعه —
  فضای اشغالی = ابعاد قطعه + kerf در هر جهتی که بعدش فضا بماند (چسبیده به لبهٔ
  صفحه kerf لازم نیست) و این نوار در تمام طول خط برش گیلوتینی حفظ می‌شود تا دو
  قطعهٔ مجاور هرگز بدون فاصلهٔ تیغه به هم نچسبند. درصد پرت شامل خوراک تیغه است.

**دستگاه مختصات:** مبدأ (0,0) گوشهٔ صفحه، X در جهت طول صفحه و Y در جهت عرض آن.
در خروجی، `width` اندازهٔ قطعه روی X و `height` اندازه روی Y است (با احتساب چرخش).

**شمای خروجی (JSON):**

```ts
interface LayoutResult {
  stock: { length: number; width: number };
  kerf: number;
  allowRotation: boolean;
  sheets: SheetLayout[];        // چیدمان به‌تفکیک هر صفحه + پرت/بهره‌وری همان صفحه
  placements: PlacedPart[];     // فهرست تخت همهٔ قطعات چیده‌شده (ورودی فاز ۳)
  unplaced: UnplacedPart[];     // قطعاتی که در هیچ جهتی در صفحه جا نمی‌شوند
  summary: {
    sheetCount: number;         // صفحات مصرفی
    wastePercentage: number;    // درصد پرت کل
    utilizationPercentage: number;
    placedCount: number; totalParts: number; /* … */
  };
}

interface PlacedPart {
  id: string;            // شناسهٔ ردیف قطعه در جدول
  name?: string;
  instanceIndex: number; // چندمین نمونه از تعداد آن ردیف (از ۱)
  sheetIndex: number;    // شمارهٔ صفحه (از ۰)
  x: number; y: number;  // نقطهٔ شروع روی صفحه (mm)
  width: number;         // اندازهٔ نهایی روی X با احتساب چرخش (mm)
  height: number;        // اندازهٔ نهایی روی Y با احتساب چرخش (mm)
  isRotated: boolean;    // چرخش ۹۰ درجه داشته؟
}
```

در رابط کاربری، بالای جدول (`LayoutPanel`) می‌توان طول/عرض صفحهٔ خام (با
پریست‌های ۳۶۶۰×۱۸۳۰ و…)، ضخامت تیغه و مجازبودن چرخش را تنظیم و با دکمهٔ
«محاسبهٔ چیدمان» الگوریتم را اجرا کرد؛ تعداد صفحات مصرفی و درصد پرت/بهره‌وری
نمایش داده می‌شود و نتیجهٔ کامل هم در کنسول مرورگر چاپ و هم به‌صورت JSON
قابل‌مشاهده/کپی است. اگر بعد از محاسبه جدول یا تنظیمات تغییر کند، نتیجه با
برچسب «قدیمی» مشخص می‌شود.

> نکته: خروجی هیوریستیک است (مثل همهٔ موتورهای Nesting تجاری) و بهینگیِ ریاضیِ
> مطلق تضمین نمی‌شود، اما سریع و برای مقیاس کارگاهی نزدیک به بهینه است.

## فاز ۳ — نقشهٔ برش (SVG) — `src/components/CuttingMap.tsx`

خروجی فاز ۲ (`sheets`/`placements`) با **SVG** رندر می‌شود؛ واحد مختصات خودِ
میلی‌متر است (`viewBox` برابر ابعاد ورق خام) پس نقشه در هر اندازه‌ای شارپ و با
حفظ نسبت ابعاد دیده می‌شود. با کلیک «محاسبهٔ چیدمان»، نقشه بلافاصله زیر کارت‌های
آماری ظاهر می‌شود (برای هر ورق خام یک نمای مجزا با بهره‌وری/پرت همان ورق).
دکمه‌های زوم (۵۰٪ تا ۳۰۰٪ + بازنشانی) و اسکرول افقی برای ورق‌های بزرگ وجود دارد.

- نقشه **سیاه‌وسفید** است: بدنهٔ همهٔ قطعات سفید با حاشیهٔ مشکی است؛ پرت با
  هاشور خاکستری/مشکی مشخص می‌شود و فاصله‌های باریک بین قطعات همان خوراک تیغه (Kerf) است.
- برچسب مرکز قطعه: نام + ابعادِ روی صفحه؛ در قطعهٔ چرخیده متن هم ۹۰- درجه
  می‌چرخد. در قطعات کوچک برچسب پله‌ای ساده می‌شود (فقط ابعاد، بعد فقط شمارهٔ
  نمونه) و جزئیات کامل همیشه در tooltip هر قطعه هست.
- بخش رسم هر قطعه در زیرکامپوننت داخلی `PlacedPart` جدا شده و فلگ‌های کارگاهی
  را از ردیف متناظر قطعه می‌خواند — از روی **اسنپ‌شات لحظهٔ محاسبه**، تا ویرایش
  بعدیِ جدول، نقشهٔ نمایش‌داده‌شده را بی‌صدا تغییر ندهد (همان مکانیزم «نتیجهٔ قدیمی»).

**قرارداد رندر علائم کارگاهی** — نگاشت لبه‌ها به چرخش قطعه حساس است: فلگ «طول»
یعنی دو لبهٔ موازی با محور طول قطعه؛ اگر قطعه ۹۰ درجه چرخیده باشد، این لبه‌ها روی
نقشه چپ/راست‌اند (و لبه‌های «عرض» بالا/پایین).

- **نوار (PVC)** ← برچسب خوانای `PVC` با فونت Arial/Vazirmatn در فاصلهٔ ۳ تا ۴
  میلی‌متر داخل قطعه و در امتداد همان لبه؛ روی لبهٔ عمودی متن ۹۰ درجه می‌چرخد.
  یک هالهٔ سفید دور حروف، متن را از خط‌چین شیار جدا و در پرینت سیاه‌وسفید خوانا می‌کند.
- **فارسی ۴۵°** ← خط ممتد مشکی + **مثلث مشکی پر** + برچسب `45°` مشکی
- **شیار** ← خط‌چین ضخیم مشکی (نسبت `8,4` و ضخامت ۲٫۵ برابر مقیاس) موازی لبه،
  دقیقاً ۱۰ میلی‌متر داخل قطعه و با فاصلهٔ ۱۰ میلی‌متر از گوشه‌های آن

اگر چند عملیات روی یک لبه باشند (مثلاً نوار + فارسی)، علائم با فاصله‌های پلکانی
پشت سر هم به داخل قطعه رسم می‌شوند تا روی هم نیفتند.

## فاز ۴ — خروجی‌ها (چاپ نقشه + لیست قطعات / DXF / لیبل)

بعد از «محاسبهٔ چیدمان» یک نوار ابزار خروجی بالای نقشه ظاهر می‌شود. اگر داده‌ها
بعد از محاسبه تغییر کرده باشند (نتیجه «قدیمی» باشد) خروجی‌ها غیرفعال می‌شوند تا
خروجی اشتباه به کارگاه نرود. همهٔ خروجی‌ها از همان اسنپ‌شات لحظهٔ محاسبه ساخته
می‌شوند و نگاشت لبه‌ها (با احتساب چرخش) از ماژول مشترک `src/partEdges.ts` می‌آید.

### ۱) پرینت نقشه (PDF/Print)

- با `window.print()` نیتیو مرورگر؛ بدون کتابخانه. برای PDF کافی است در دیالوگ
  چاپ «Save as PDF» انتخاب شود.
- سند چاپی در یک **Print Portal** روی `body` رندر و روی صفحه مخفی است؛ در حالت
  چاپ (`html[data-print-mode]` + `@media print` در `index.css`) کل اپ مخفی و فقط
  سند چاپی (سربرگ خلاصه + نقشه‌ها + فهرست قطعات) چاپ می‌شود. پرینت دستی با Ctrl+P
  دست نمی‌خورد.
- خروجی سیاه‌وسفید و هاشورها با `print-color-adjust: exact` حفظ می‌شوند و سند نقشه با صفحهٔ نام‌دار
  روی **A4 افقی (Landscape)** تنظیم شده؛ هر ورق خام یک‌تکه می‌ماند (`break-inside: avoid`).
- در دکمهٔ واحد **«چاپ نقشه و لیست قطعات»**، زیر همهٔ SVGهای نقشه **جدول
  گروه‌بندی‌شدهٔ قطعات** (تعداد، ورق‌ها، کدهای نقشه، شرح عملیات و مربع تیک) و سپس
  **فاکتور متریال مصرفی** در همان سند چاپ می‌شود. جدول با `table-header-group` و
  `break-inside: avoid` روی ردیف‌ها، در صورت طولانی‌بودن بدون به‌هم‌ریختگی به صفحهٔ
  بعد ادامه می‌یابد و عنوان/فاکتور از جدول جدا نمی‌شوند.

### ۲) خروجی DXF برای CNC — `src/exportDxf.ts`

- تولیدکنندهٔ متنی سبک **DXF R12 (AC1009)** بدون وابستگی خارجی؛ واحد میلی‌متر.
- هر قطعه یک `POLYLINE` بسته در لایهٔ `CUT` است؛ کادر ورق‌ها در `SHEET` (چند ورق با
  فاصلهٔ ۱۰۰ میلی‌متر کنار هم + عنوان `SHEET n`)، خطوط شیار در `GROOVE` (موازی لبه،
  فاصلهٔ ۱۰ میلی‌متر داخل قطعه) و خط مورب ۴۵° در مثلث گوشه‌های لبهٔ فارسی در `FARSI_45`.
- کد هر قطعه (مثل `S1-03`) در مرکزش و در لایهٔ `LABEL` نوشته می‌شود؛ همان کدی که
  روی لیبل چاپی می‌آید. متن‌های DXF فقط ASCII است (نام فارسی در DXF امن نیست).
- «نوار» عمداً هندسهٔ DXF ندارد (عملیات برش نیست و خط روى لبه ممکن است اشتباه
  ماشین‌کاری شود)؛ جایش روی نقشهٔ چاپی و لیبل است.
- مختصات به دستگاه CNC تبدیل می‌شود: مبدأ هر ورق گوشهٔ پایین-چپ و Y رو به بالا
  (`dxfY = stockWidth - y - height`)؛ لبه‌ها بعد از تبدیل سر جای فیزیکی خودشان‌اند.

### ۳) لیبل قطعات — `src/components/LabelSheet.tsx`

- شبکهٔ **۳ ستون × ۵ ردیف در هر A4 عمودی (Portrait)**؛ هر ۱۵ لیبل یک صفحه با
  `break-after: page` جدا می‌شود و خانه‌های خالی صفحهٔ آخر برای تراز کاغذ برچسبی
  خالی می‌مانند.
- هر لیبل: کد قطعه، نام، ابعاد قطعه (+ ابعاد چرخیده روی نقشه اگر چرخیده)، شمارهٔ
  ورق و نمونه، مختصات روی ورق، علائم متنی هر عملیات («نوار: طول و عرض»،
  «فارسی ۴۵°: فقط طول»، «شیار: ندارد» و…) و یک شماتیک کوچک از لبه‌ها با همان
  نگاشت عملیات و چرخشِ نقشه.
- دکمه‌های «چاپ لیبل‌ها» (همان Print Portal، حالت labels) و «پیش‌نمایش لیبل‌ها»
  برای دیدن همان سند روی صفحه قبل از چاپ وجود دارد.

### ۴) برگهٔ کنترل تولید — `src/components/ControlSheet.tsx`

- برگهٔ روی‌صفحه همان جدول کنترلی است: هر قطعهٔ چیده‌شده یک ردیف مستقل با کد مشترک
  نقشه/لیبل، ابعاد، ورق، مختصات، چرخش و **شرح عملیات متنی** دارد؛ هر ردیف یک مربع
  خالی بزرگ برای تیک کنترل کارگاهی دارد.
- همین جدول در سند چاپی نقشه (با دکمهٔ «چاپ نقشه و لیست قطعات») به شکل
  **گروه‌بندی‌شده** هم می‌آید: قطعات هم‌نام/هم‌ابعاد با شرح عملیات یکسان در یک ردیف با
  ستون تعداد و فهرست کدهای نقشه جمع می‌شوند. دکمهٔ جداگانهٔ «چاپ برگه کنترل» حذف شده
  است تا اپراتور همه‌چیز را یک‌جا بگیرد.
- فاکتور تخمینی متریال در انتهای برگه و انتهای سند چاپی، متراژ کل نوار، لبهٔ فارسی و
  شیار را بر حسب متر با احتساب مقدار ۰/۱/۲، ابعاد و تعداد هر قطعه نشان می‌دهد.

## فاز ۵ — مدیریت پروژه‌ها (Save / Load / Manage)

مدل پروژه در `src/types/project.ts` و لایهٔ ذخیره‌سازی در `src/storage/projects.ts`:

```ts
interface Project {
  id: string;
  name: string;
  createdAt: number;
  updatedAt: number;
  parts: CutPart[];
  settings: { stockLength: number; stockWidth: number; kerf: number; allowRotation: boolean };
  lastLayout?: LayoutResult;   // آخرین نقشهٔ محاسبه‌شده (بازشدن فوری بدون محاسبهٔ مجدد)
  lastLayoutParts?: CutPart[]; // اسنپ‌شات قطعات همان محاسبه (مبنای علائم نقشه)
}
```

- **ذخیره‌سازی:** فهرست پروژه‌ها در `localStorage` با کلید **`acut_projects`**.
  علاوه بر آن، فضای کاری فعلی به‌صورت خودکار در کلید `acut_draft` نگه داشته
  می‌شود تا رفرش صفحه کار جاری را از بین نبرد (با مهاجرت خودکار از کلید قدیمی
  قطعات فازهای قبل). «ذخیرهٔ پروژه» عمل صریح کاربر است و جدا از پیش‌نویس خودکار.
- **هدر برنامه:** سمت راست لوگوی A-Cut 2Dpro و اطلاعات سازنده (**عباس کروشاد** —
  اینستاگرام/تلگرام `@Webxplusx`) و سمت چپ وضعیت پروژهٔ جاری + دکمهٔ Dropdown
  «مدیریت پروژه‌ها» (ذخیره، ذخیره با نام جدید/Save As، پروژهٔ جدید، باز کردن پروژه
  و پنج پروژهٔ اخیر).
- **مودال پروژه‌ها** (`ProjectManager.tsx`): جستجو بر اساس نام؛ برای هر پروژه نام،
  تاریخ آخرین ویرایش، تعداد ردیف/قطعه، ابعاد ورق و نشان «دارای نقشهٔ برش» نمایش
  داده می‌شود و دکمه‌های [باز کردن] و [حذف] دارد. حذف و بازکردن/پروژهٔ جدید هنگام
  داشتن تغییرات ذخیره‌نشده ابتدا تأییدیه می‌گیرد.
- **باز کردن پروژه** همهٔ Stateها را برمی‌گرداند (قطعات، تنظیمات ورق و تیغه،
  گزینهٔ چرخش) و اگر `lastLayout` ذخیره شده باشد نقشهٔ برش بلافاصله رندر می‌شود؛
  امضای آن از روی اسنپ‌شات ذخیره‌شده بازسازی می‌شود تا برچسب «نتیجهٔ قدیمی»
  دقیقاً مثل قبل از ذخیره رفتار کند.
- **تغییرات ذخیره‌نشده (Dirty):** با مقایسهٔ امضای فضای کاری با آخرین وضعیت
  ذخیره‌شده تشخیص داده می‌شود؛ در هدر و منو با نشان کهربایی دیده می‌شود و هنگام
  بستن/رفرش صفحه، `beforeunload` به کاربر هشدار می‌دهد.
